# 평가 설계 원칙 (Assessment Design)

> 대상: 이 제품이 "무엇을 어떻게 측정하는가"의 확정된 결정.
> 스키마·RLS 는 `MULTITENANT_DESIGN.md`, 이 문서는 **문항·채점·AI 접속·공정성**.
> `0007`(시험 도메인)·문항 유형 enum·응시 화면 이식은 이 문서를 참조점으로 삼는다.

## 0. 한 문장

**생성형 AI 활용 역량**을, **답은 결정론적으로 채점되지만 과정에서 AI 를
정확히 부리지 못하면 못 푸는** 작업형 문항으로 측정한다. AI 가 응시자를
채점하지 않는다 — 응시자가 AI 를 얼마나 잘 부리는지를 채점한다.

## 1. 이름과 첫 오해

"AI 역량평가"는 한국어에서 두 가지로 파싱된다.

- `AI[가] 역량평가` → AI 가 나를 채점한다 (평가의 **주체**가 AI)
- `AI[활용] 역량평가` → AI 쓰는 능력을 평가한다 (평가의 **대상**이 AI활용)

사람들은 앞쪽(AI 면접·표정분석 학습됨)을 먼저 떠올린다. 우리는 뒤쪽이다.
말로 설명해도 안 지워지므로 **이름에 '활용'을 박아** 파싱을 고정한다.
표준 표기: **"AI 활용 역량평가"**.

## 2. 왜 결정론 채점인가 (AI 채점을 일부러 안 쓴다)

채용은 차별금지법 영역이다. AI 가 점수를 매기면:

| AI 채점 시 | 결과 |
|---|---|
| 왜 이 점수? | 설명 불가(블랙박스) |
| 지원자 이의제기 | 방어 못 함 |
| 편향 시비 | 실제 소송 리스크(adverse impact) |
| 재현성 | 같은 답도 점수가 흔들림 |

결정론 채점("답이 3인데 5를 쓰셨습니다")은 반박 불가하고, 100명 채점 원가가
≈0 이다. 이것은 약점이 아니라 **신뢰 기능**이다.

AI 가 개입하는 자리는 채점이 아니라 **응시자의 손**이다(§5).

## 3. 함정 설계 — 답은 싸게, 과정은 AI 없이 불가

단답형인 이유: 채점 용이. 하지만 **과정에서 생성형 AI 를 정확히 부리지
못하면 못 푼다.** 함정 유형:

| 함정 | 예 | 재는 역량 |
|---|---|---|
| 근접 오답 배치 | 한 문단에 노출수/클릭수/도달수/전환수 → "전환수만" | 질문 좁히기 |
| 분산 집계 | 금액이 5개 문서에 흩어짐 → 합계 | 자료 전체 투입 + 정확 지시 |
| 조건 복합 | 결측 제거 → IQR 제거 → 집계(순서 강제) | 처리 절차를 AI 에 정확 전달 |
| 형식 강제 | CSV 컬럼 2개·내림차순·UTF-8 | 산출물 스펙 지시 |
| 가상 자료 | 존재하지 않는 법·지표 | 검색·사전지식 무력화 → 자료 반드시 처리 |

**가상 자료가 부정행위 방지의 핵심이다.** 검색해도 안 나오고 AI 사전지식에도
없으므로, 첨부를 실제로 처리해야만 답이 나온다.

## 4. 문항 생산 — 템플릿 × 소재팩 × seed (덧셈이다)

손으로 만들면 문제은행이 병목이 된다(특히 상시 채용). 해결:

**정답을 먼저 정하고, 그 정답이 나오도록 자료를 생성한다.** 사람이 자기가 쓴
글을 다시 세지 않는다 — 정답은 생성 파라미터다. 검산 불필요, 오답 리스크 0.

```
문항 템플릿 = (자료 생성기, 질문 문형, 정답 함수, 함정 규칙)
소재팩(직무의 옷) = (지표 사전, 조직명 풀, 문서 서식)
세트 = 템플릿 × 소재팩 × seed        # seed 무한, 유출돼도 다음 회차 숫자 다름
```

**직무군은 곱셈이 아니라 덧셈이다.** 마케팅·영업·생산… 은 소재팩 하나씩
추가하면 된다(직무당 ~20분: 용어·지표·서식만). 문항·자료·정답·함정은 템플릿이 찍는다.

- 계획 규모: 템플릿 5종 + 소재팩 8직무 = **13개를 만들면** 40개 조합 × seed 무한
- 개념 증명 완료: "분산 집계형" 1종. 마케팅·생산 소재팩으로 교차 생성 + 독립 검산 통과
- 부산물: 응시자 ID 워터마크(자료 주석), 회차별 재생성 → **캡처·복붙 차단 불필요**

### 과제 유형 → 채점 비용

| 과제 유형 | 채점 | 비용 | 기본 배점 |
|---|---|---|---|
| 문서검토 / 데이터처리 / 분석 / 콘텐츠수집 / 문서편집 | 정수·문자열·스펙 대조 | 싸다 | 90점 |
| 업무자동화(산출물) | 스펙 대조 + 실행 | 중 | (블루+) |
| 문서생성 / 콘텐츠생성 / 디자인 | AI·사람 채점 | 비싸다 | 10점 상한 |

디자인은 초기 제외(채점 원가가 나머지 합보다 큼).

## 5. AI 접속 — 두 모델, 유형이 알아서 갈린다

```
BYO-AI(제 AI 가져오기)  : 응시자가 자기 무료 챗봇으로 산출물 제작 → 제출.
                          AI 가 우리 서버 안 거침. 우리 비용 0. 문항의 ~90%.
내장 AI(우리가 제공)     : 시험 화면 내 챗봇. 토큰당 우리 지불. 좁게만 사용.
```

**산출물이 증거면 AI 가 어디 있었는지 무관하다.** Python 파일은 실행해서,
HTML 은 렌더해서 채점한다. 내장이 필요한 경우는 좁다:

- 콘솔 실행·MCP·스킬 연결처럼 **환경 자체가 시험**인 경우(블랙)
- 프롬프트 로그 기반 **과정 점수**(프리미엄)
- 고신뢰 시험의 **공정성**(§6)

기반은 이미 있음: `supabase/functions/_shared/ai.ts` 가 공급자 중립
(`AI_BASE_URL`/`AI_API_KEY`/`AI_MODEL`). 세션별 프롬프트 로깅만 얹으면 됨.
**응시자별 토큰 상한 필수**(내장 모드 비용 방어).

### Ollama / 저가 모델 경고

점수 나가는 시험의 내장 AI 에 약한 모델을 쓰면, 좋은 프롬프트로도 못 푸는
문항이 생겨 **난이도가 응시자 실력이 아니라 우리 모델 성능에 묶인다.** 공정성
붕괴. 따라서:

- **연습·자가진단** → Ollama/저가 가능(비용 0 수렴)
- **점수 시험** → BYO 무료 티어(응시자 선택) 또는 프런티어 API(엔터프라이즈 가격에 포함)

## 6. 공정성 헷징 (AI 접속 격차) — 채용 필수

지원자 A=Plus, B=무료면 형평 시비. 소득↔티어↔보호계층 대리변수가 되면
adverse impact. **공정하다고 우기지 말고 설계로 헷징한다. 4겹:**

1. **설계 게이트** — 모든 platform 문항은 "무료 티어로 풀리는가"를 출제 검증
   항목으로 강제. 티어 차이를 소스에서 무력화(합계는 Plus라고 더 정확하지 않다).
2. **모델 중립** — 특정 모델 기능 요구 금지. 무료 티어 최소공통분모만.
3. **시간 여유** — 무료 rate limit 이 안 걸릴 만큼 제한시간 설정(속도 이점 제거).
4. **고신뢰=환경 제공** — 블랙/인증은 BYO 폐지, 전원 동일 내장 AI. 티어 편차 0.

핵심은 1번: "무료로 충분"이 사실이면 티어가 차별을 만들 수 없다.

### 단, "도구 선택·조합"은 역량이다 (헷징을 오해하지 말 것)

위 헷징은 "유료 도구 활용을 재지 말라"가 아니다. 두 가지를 가른다:

- **도구 선택·조합 판단** = 역량(응시자 정의 ①②). **재야 한다.**
  단 결제를 요구하지 말고 — 환경에 도구를 여럿 깔고 무엇을 집어드는지,
  "왜 이 도구인가"를 보면 여력이 아니라 판단을 잰다.
- **결제 여력** = 지갑. 역량 아님.

그리고 **맥락이 티어의 정당성을 가른다:**

| | 채용(지원자가 냄) | 사내 인증(회사가 도구 제공) |
|---|---|---|
| 티어 격차 | 여력이 실력으로 둔갑 → 불공정 | 회사가 균등 지급 → 균등 |
| 고급 도구 숙련 측정 | 안 됨(법적 리스크) | **정당함** |

**원칙: 접근을 균등화한 뒤에 재면 티어는 지갑이 아니라 실력이 된다.**
내장 AI·환경 제공(§5)의 진짜 목적이 이것 — 하향평준화가 아니라, 전원에게
같은 고급 도구를 쥐여주고 그 위에서 숙련을 재는 것. 채용 스크리닝만 무료
티어로 바닥을 맞추고, 사내 인증·블랙은 고급 도구 숙련을 잰다.

## 7. 등급 = AI 접속 = 과금, 세 개가 한 선

| 등급 | AI 접속 | 우리 비용 | 용도 / 과금 |
|---|---|---|---|
| 그린 | BYO 무료 티어 | 0 | 대량 채용 스크리닝 · SaaS 기본료 |
| 블루 | BYO + 코드 실행 채점 | 낮음 | 실무형 · SaaS 기본료 |
| 블랙 | **환경 제공**(콘솔·MCP·프런티어) | 높음 | 인증·고신뢰 · **엔터프라이즈 별도가** |

공짜가 바닥(대량 스크리닝), 유료 환경이 꼭대기. 원가가 매출 구조와 자동 정렬.

**미해결:** 블랙 등급의 원본 실제 문항을 아직 못 봄. §7 은 추정이며 블랙 샘플
확인 후 확정.

## 8. 문항 소유권 = 과금 모델 (이미 `0006` 에 구현)

```
platform  = 우리가 만든 기본 문항은행     → SaaS 구독료
licensed  = 유료 구매 세트                → 애드온
org       = 고객사 직원이 직접 출제       → 조직 내부
맞춤 설계  = 영업팀 → 컨설팅비 (SaaS 밖)   → 함정·정답 검증 노동이라 구독료로 불가
```

## 9. FAQ (초안)

### 9-1. 응시자용 (응시 화면·안내 메일에서 노출)

**Q. 유료 AI 구독이 있어야 유리한가요?**
아니요. 모든 기본 문항은 무료 AI(ChatGPT·Claude·Gemini·Copilot 무료)로 풀
수 있도록 설계·검증됩니다. 유료 구독이 정답을 더 정확하게 만들지 않습니다.

**Q. 어떤 AI 를 써야 하나요?**
자유입니다. 특정 서비스를 지정하지 않습니다. 단, 고신뢰(인증) 등급은
전원 동일 조건을 위해 플랫폼이 제공하는 AI 만 사용합니다.

**Q. AI 가 제 답을 채점하나요?**
아니요. 채점은 정해진 정답과의 대조입니다. AI 가 점수를 매기지 않으므로
같은 답은 항상 같은 점수를 받습니다.

**Q. 제 프롬프트(AI 와 나눈 대화)를 회사가 보나요?**
플랫폼 제공 AI(내장 모드)를 쓰는 시험은 프롬프트가 평가 근거로 기록될 수
있으며, 시작 전 고지됩니다. 본인 AI 를 쓰는 시험은 산출물만 제출됩니다.

**Q. 인터넷/검색을 써도 되나요?**
됩니다. 다만 자료가 가상으로 제작되어 검색으로는 답이 나오지 않습니다.
첨부 자료를 직접 분석해야 합니다.

### 9-2. 구매자(HR)용 (랜딩 FAQ)

**Q. 지원자마다 AI 접근 수준이 다른데 공정한가요?**
기본 문항은 무료 AI 로 풀 수 있도록 설계·검증하여, 유료 구독 보유가 점수
우위를 만들지 않습니다. 합격을 가르는 고신뢰 등급은 플랫폼이 동일한 AI
환경을 전원에게 제공해 접근 격차를 제거합니다.

**Q. AI 가 지원자를 채점하나요? 편향은요?**
아니요. 채점은 정답과의 결정론적 대조입니다. AI 판단이 점수에 개입하지
않으므로 설명 가능하고 이의에 방어됩니다.

**Q. 문항이 유출되면요?**
문항은 템플릿에서 응시자·회차별로 생성되어 수치가 매번 다릅니다. 유출본이
다른 응시자의 정답이 되지 않습니다.
